## 1. Production backend Dockerfile (multi-stage)

Pattern to reinstate at v0.3 (the local runtime stays on the root `Dockerfile` + docker-compose).
**Fix on reinstate**: package name is `@oceansoft/backend` (NOT `@digital-commerce/backend`); verify the
Medusa v2 build output path (`.medusa/server` in current Medusa, not `dist/main.js`) before setting `CMD`.

Stages + key properties:
- **`deps`** — `corepack` pnpm; `pnpm install --filter @oceansoft/backend --frozen-lockfile --prod` (prod-only).
- **`build`** — full install (incl. devDeps) → `pnpm --filter @oceansoft/backend run build`.
- **`runtime`** — non-root user (`addgroup -S medusa && adduser -S -G medusa -u 1000 medusa`); copy prod
  `node_modules` from `deps` + compiled output from `build`; `EXPOSE 9000 7001`;
  `HEALTHCHECK CMD wget -qO- http://localhost:9000/health || exit 1`; arm64/Graviton target.
- **`dev`** — full deps, `CMD pnpm --filter @oceansoft/backend run dev`; used by docker-compose (target: dev), never published.

Storefront needs an equivalent `apps/storefront/Dockerfile` (multi-stage Next.js standalone) before the
release pipeline's `build-storefront` job can run — it did not exist at salvage time.

## 2. Tag-only release pipeline (`release.yml`)

Reinstate as `.github/workflows/release.yml` at v0.3. Design (ADR-006-aligned):

- **Trigger**: `on: push: tags: ['v*.*.*']` only — never on branch push (Principle I: humans cut releases).
- **Permissions**: `contents: write` (release-please changelog), `packages: write` (GHCR), `id-token: write` (OIDC AWS), `pull-requests: write`.
- **Jobs**:
  1. `release-please` — `google-github-actions/release-please-action@v4`, `release-type: node` → changelog + tag outputs.
  2. `build-backend` — buildx → GHCR `…/digital-commerce-backend`; `file: apps/backend/Dockerfile`, `target: runtime`,
     `platforms: linux/arm64`; `docker/metadata-action` semver+sha tags; `provenance: true`, `sbom: true`, GHA cache.
  3. `build-storefront` — same, with `build-args: NEXT_PUBLIC_MEDUSA_BACKEND_URL`, `NEXT_PUBLIC_BASE_URL` from repo vars.
  4. `iac-security` — `nnthanh101/terraform:slim`: `terraform fmt -check`, `checkov --soft-fail`, `trivy config`.
  5. `deployment-gate` — writes a `$GITHUB_STEP_SUMMARY` table + **HITL action note**: "update `medusa_image` in tfvars
     and run `task tf:plan ENV=dev`". **No `terraform apply` / `cdk deploy` in CI** (Principle I — deploy is HITL-gated).
- **Registry**: `ghcr.io/${owner}/digital-commerce-{backend,storefront}`. **Image-tag note**: pin a real
  `nnthanh101/terraform` tag (`:slim`) — `:latest`/`:2.6.0` are not reliable (see `image-preflight.yml` guard).
